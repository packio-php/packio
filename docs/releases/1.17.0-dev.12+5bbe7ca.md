## Limitations and upgrade baseline

This is **preview**, with no stable production-readiness or maintenance-window promise. The minimum backup runbook was checked in the candidate checkout/archive. Fresh same-candidate restore, upgrade, rollback, readiness-failure and limiter-lifecycle drills and a stable SBOM have not been performed. Earlier operations results are historical evidence for their original artifacts.

The exact selected upgrade baseline is `v1.15.1` / `42f27b9f43ef9a571d5284dffb02f0aae65eb1f6`. This draft does not validate upgrading nonempty data from that baseline. Preserve the original encryption key with protected database/archive/configuration backups; live key rotation and zero-downtime upgrades are outside this claim.

Experimental S3 was skipped in the base suite and is **not tested** for this candidate. SQLite, arm64, production FrankenPHP/legacy standalone runtimes, arbitrary historical upgrades and S3 recovery are outside the supported preview matrix.

Deferred maintenance remains visible: broader first-party architecture coverage (M1), Source facade contracts (M2), mapper query-budget measurement (M3), and Link/Svelte state simplification (M4). Each requires its own plan; none is presented as completed here.
