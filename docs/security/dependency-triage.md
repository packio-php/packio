# Frontend dependency advisory triage

Status: all initial findings resolved and the complete frontend/runtime checks of the 2026-10-11 verification passed on Node 24.18.0. This records working-tree verification, not release approval.

## Scope and method

The baseline was the complete npm lockfile at source HEAD `bbda3c0295bdee690709632b10ebe05df93d6c3f`, inspected on 2026-10-11 with `npm ci`, `npm audit --json`, `npm ls --all`, and `npm explain`. It contained 13 affected packages (7 high, 6 moderate), covering 41 distinct advisories. Omitting devDependencies would hide this frontend graph: the Docker build installs it and produces both the browser assets and the SSR bundle.

The supported target is Node 24.21.0 with its supplied npm. The evidence from the 2026-10-11 verification records the previous Node 24.18.0/npm 11.16.0 target; a later verification covers the updated runtime. Production and local SSR Docker stages, the Vite Compose service, `.nvmrc`, package engines, and the proxy browser runner use that exact Node version. The existing frontend workflow already selects it. Earlier Node 22.22.2/npm 10.9.7 graph-resolution failures are historical; their results do not verify this target.

Compatible fixes retain the original major versions. The Vitest/coverage declarations now require at least 4.1.11 because automatic resolution with the old 4.1.9 minimum reselected the vulnerable peer pair. Both ranges remain within their previous `^4.1.9` bounds. The remaining patches were limited to affected packages and the matching Vitest family; the unrelated Chai version stays at 6.2.2.

The application uses Svelte components in its client build and SSR. `resources/js/ssr.ts` imports `render` from `svelte/server`; the installed Svelte server renderer and hydratable renderer import `devalue`, and the production SSR image runs the generated `data/ssr/ssr.mjs` bundle. Thus `devalue` is an SSR-reachable dependency even though it is declared transitively under a devDependency. The SSR endpoint accepts JSON page data up to 1 MiB; dependency reachability does not by itself establish that every advisory is exploitable through Packio. The fixed version is bundled and exercised by the actual production SSR/browser fixture.

The SvelteKit install was peer-installed through the then-declared `@sveltejs/adapter-node`; the source, build scripts, Svelte/Vite configuration, and current SSR entry do not use SvelteKit or that adapter. The reviewed change removes both unused declarations rather than taking the advisory's breaking `sharp` update. `sharp` likewise had no source or script consumer and is removed. The `cookie` override is retained; it is not one of the findings in this audit.

## Verification

Run these commands with the supported Node 24.21.0 and its supplied npm:

```sh
npm ci --no-audit --no-fund
npm run check
npm run openapi-assets
npm audit --json
npm ls --all
npm ci --no-audit --no-fund
```

`npm run check` must run in a browser-ready environment matching locked Playwright 1.62.1; it includes types, lint, Inertia guards, frontend tests, built SSR tests, real Chromium tests, formatting, and client/SSR builds. The second install must leave both npm manifests unchanged. A full audit includes devDependencies; `--omit=dev` does not check the shipped JavaScript.

The production `prod-ssr` target must start with its actual filesystem, which contains the built SSR bundle and no application `node_modules`. Verify that exact image with the existing proxy harness against disposable PostgreSQL/app resources, including real SSR/hydration/navigation and positive/negative CSRF controls. Working tree/image checks do not establish a clean release candidate, image provenance, or publication approval.

The runtime SSR proof uses the image's shipped bundle with no host filesystem mounted. `devalue` is bundled through Svelte's server renderer, despite the npm devDependency classification. Static SSR imports are Node built-ins; successful real rendering verifies this artifact does not require an external application package graph. Tests establish integration behavior; they are not independent exploit regressions for every upstream advisory. The first working-tree check exposed ESLint errors in Git-ignored local agent/journal files; the narrow global ignores `.codex/**` and `local-plans/**` exclude those local inputs while preserving all product/test/tool/config lint rules. No advisory exceptions, owners, expiries, or release approval are claimed.
